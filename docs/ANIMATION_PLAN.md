# Nate 애니메이션 점검과 제작 계획

현재 실행 팩은 `local-assets/nate-animation-review/current-characters/nate-v6`다. 사용자가 선택한 **A idle은 몸과 시선 고정·눈 깜빡임만**를 사용한다. walk는 수용한 **8개 핵심 자세·8 FPS**를 유지하고 한 번의 걷는 시간을 약 두 배로 늘렸다. 아래 고정 idle과 첫 시험 팩의 구성은 이전 검증 기록이다.

## 확정한 표시 크기

2026-10-04 사용자가 기존 Nate 임시 팩을 1.5배로 표시한 288×312픽셀 크기를 수용한 뒤, 다른 제작자도 사용하기 쉬운 규격 정리를 요청했다. 새 Nate 팩은 320×320픽셀 투명 PNG로 제작하고 전신 높이는 약 300픽셀, 바닥 기준선은 y=308으로 맞춘다. 그림의 종횡비를 늘리지 않는다. 기본 제작 권장값이며 다른 팩에 정사각형을 강제하지 않는다. 다른 DPI의 체감 크기는 아직 확인하지 않았다.

## 현재 이미지 점검

임시 팩은 idle 6장, walk 8장, happy 4장이다. 확인한 walk 표본에는 무릎을 높이 올리고 보폭을 크게 벌리는 달리기 자세가 있어 FPS만 높여서는 자연스러운 걷기가 되지 않는다. 기존 그림의 만화식 눈과 신발도 공식 레퍼런스의 실제 눈에 가까운 표현·맨발 기준과 다르다.

공식 레퍼런스는 `D:\Nate stiker collation_1\images.jpg`의 전신 비율과 `D:\Nate stiker collation_1\OrCYDa.png`의 눈·셔츠 표현이다. 이전 초안과 `canonical-base.png`는 새 외형의 기준으로 사용하지 않는다.

내장 image_gen 도구로 새 전신 후보를 제작했고 사용자가 두 번째 후보의 외형을 수용했다. 기준 원본은 `local-assets/nate-animation-review/artwork/nate-master-candidate-v2.png`, 사용한 전체 프롬프트는 같은 폴더의 `prompts.md`와 `animation-prompts.md`에 있다. 확인한 배경 표본의 알파는 0이다. 미리보기에 보이는 회색 번짐은 해당 투명 픽셀의 RGB 정보로, 실제 배경으로 단정하지 않는다.

## 다음 제작 순서

1. 전신 후보의 외형을 사용자와 확정한다. 원본과 임시 팩은 보존한다.
2. 사용자가 선택한 A idle은 같은 몸 그림을 유지하면서 눈 깜빡임·작은 시선 변화만 넣는다. B 호흡 후보는 보관한다.
3. walk는 레퍼런스의 접지·체중 이동·통과·밀어내는 자세를 양쪽 다리에 적용해 핵심 자세부터 확인한다. 올바른 중간 자세가 확보될 때 프레임 수를 늘린다. 전신 중심·머리 크기·바닥 기준선과 마지막→첫 프레임 연결을 확인한다.
4. 320×320 실행용 캔버스로 추출·축소하고 새 테스트 팩에서 실제 표시와 입력을 확인한다. 확대 필터의 외형과 비용도 필요할 때 비교한다.
5. 늘어난 실제 프레임으로 쉬기·걷기·전환 및 반복 실행의 CPU·메모리·처리 지연을 다시 측정한다. 반복 디코딩이 병목이면 바이트 상한을 둔 작은 캐시를 적용하고, 같은 조건에서 증가한 메모리와 줄어든 처리 비용을 비교한다.

타이머·메뉴와 추가 행동은 이 단계에 넣지 않는다. 원본 Nate 임시 팩과 새 이미지 후보는 Git에 추가하지 않는다.

## 320 규격의 첫 시험 팩

`local-assets/nate-animation-review/new-characters/nate-v2`에 idle 12장·8 FPS, walk 16장·16 FPS를 준비했다. 생성 원본은 idle 1391×1131, walk 두 번째 후보 1254×1254였다. 셀 경계를 실제 픽셀 좌표로 계산해 추출하고, 모션별 공통 배율과 머리 가로 중심·바닥 기준으로 정렬했다. alpha를 곱한 색으로 Lanczos3 축소 후 실행용 straight RGBA로 되돌려 투명 픽셀의 숨은 RGB가 가장자리로 번지는 것을 줄였다. 28장 모두 320×320이며 테두리는 완전 투명하고 파일 해시가 서로 다름을 확인했다. 이는 자연스러운 동작의 증거는 아니다. 원본·임시 팩은 보존했다.

첫 walk 시트는 비슷한 자세가 여러 장 이어지고 idle과 머리 크기가 달라 두 번째 후보를 만들었다. 현재 시험 팩도 자세별 회전·넓이와 반복 연결을 더 검수해야 하며 자연스러운 최종 보행으로 확정하지 않았다. 실제 접지점의 이동 속도 일치, idle↔walk 전환과 좌우 반전의 시각적 품질도 남아 있다.

280회 PNG 읽기·디코딩 측정은 중앙값 0.463 ms, 95백분위 0.530 ms, 최대 0.669 ms였다. scale=1.0이며 GDI 표시 시간은 제외한다. 릴리스 프로세스를 각각 약 12.68초 측정한 두 실행은 코어 하나 기준 CPU 0.86% / 0.99%, 최대 작업 집합 18.52 / 11.00 MiB, 최대 전용 메모리 4.05 / 3.11 MiB였다. OS 작업 집합 관리와 무작위 행동 시간이 달라 실행 간 우열로 해석하지 않는다. 시간 제한 후 해당 테스트 프로세스를 강제 종료했으므로 정상 종료 코드 검증으로 기록하지 않는다. 긴 실행 메모리 안정성과 새 팩의 입력·다중 모니터·DPI 검증은 남아 있다. 전체 프레임 선로딩이나 캐시는 추가하지 않았다.

자체 포함형 `local-assets/nate-animation-review/preview.html`은 기존 팩과 새 팩의 쉬기·걷기, 재생·일시정지·프레임 이동, 배경 전환을 제공한다. 로컬 브라우저에서 두 모션 재생과 일시정지·프레임 이동을 확인했다. 앱 성능 측정용 화면은 아니다. 프레임·원본·프롬프트·원시 측정 결과는 `local-assets/nate-animation-review`에 보존했으며 `.gitignore`로 Git 추가를 방지했다. 프로파일링용 임시 프로그램은 `target/animation-check`에 남긴다. 기본 실행 팩에는 적용하지 않았다.

## 정지 고정과 보행 레퍼런스 반영

2026-10-04 사용자는 idle의 불규칙한 흔들림과 걷기에서 다리가 사라졌다 나타나는 표현을 지적했다. idle은 v2의 첫 PNG를 그대로 복사한 한 장만 쓰고, 다른 프레임을 섞거나 호흡 모션을 넣지 않는다. 실제 엔진은 단일 프레임 idle에서 행동 판단 간격으로 타이머를 설정하는 기존 경로를 사용한다.

보행 기준은 [Monmouth 대학의 애니메이션 수업 자료](https://animation.monmouth.edu/instruct/animation/walk-cycle/)와 해당 페이지의 `PuppetWalk4.gif`다. 접지·체중을 받는 자세·반대쪽 다리의 통과·밀어내기 및 반대 발의 반 주기를 참고했다. 참고 그림은 `artwork/walk-reference-monmouth.png`에 있으며 출처와 내장 image_gen 도구의 전체 프롬프트는 `artwork/revision-v3-prompts.md`에 기록했다.

검은 다리가 배경과 구분되도록 불투명한 연두 배경에서 8개 핵심 자세를 만든 뒤, 이미지 도구로 배경을 투명화했다. v3는 측면 방향을 고정하고 양쪽 다리를 어두운 톤으로 구분했다. PNG 9장 모두 320×320이며 idle은 이전 첫 프레임과 파일 바이트가 같고 walk 8장은 서로 다른 파일이다. 불투명 원본의 어두운 하체 표본 중 약 97.25%가 같은 위치의 투명화 결과에서 alpha≥240이었다. 이는 테두리·자세 변화가 포함된 참고 검사이며 양쪽 다리의 해부학적 완전성을 보증하는 검사가 아니다. 재생 화면과 통과 자세의 양쪽 다리·발도 별도로 확인한다.

16장 중간 프레임 생성도 시도했지만 요청한 핵심 자세 배치·중간 순서를 지키지 않아 적용하지 않았다. 현재는 8장·8 FPS로 검수한다. 프레임 수 증가와 접지의 화면 이동 속도 일치는 아직 남은 작업이다. v3의 실행 자원은 새로 측정하지 않았으며 위 v2 수치를 v3 성능으로 표현하지 않는다. 미리보기는 v2와 v3를 모두 320×320으로 비교하며 실제 Pet 프로세스를 새로 띄우지 않았다.

## 팔 스윙과 레퍼런스 우선 제작

사용자는 v3의 보행을 수용하고 팔을 자연스럽게 움직이도록 요청했다. 앞으로 애니메이션 이미지 작업 전 해당 모션 레퍼런스를 검색하고 참고하는 규칙을 `AGENTS.md`와 `IMAGE_GEN_TEMPLATE.md`에 반영했다.

팔 스윙은 [Animation Mentor의 기본 보행 튜토리얼](https://www.animationmentor.com/blog/tutorial-animating-human-walk-cycle/)과 [Alice의 보행 참고 문서](https://www.alice.org/wp-content/uploads/2019/03/BipedWalkCycleQuickReference.pdf)를 확인했다. 반대 팔·다리의 교차, 과하지 않은 스윙, 팔꿈치·손목의 지연을 기준으로 수용한 v3 시트를 내장 image_gen 도구에서 부분 수정했다. 전체 프롬프트와 출처는 `artwork/revision-v4-prompts.md`, 생성 원본은 `artwork/walk-v4-arm-swing.png`에 보존했다.

v4는 8장·8 FPS를 유지하고 팔이 뒤→옆→앞→옆→뒤로 움직이며 손은 힘을 푼 자세로 바꿨다. idle은 v3와 파일 바이트가 동일한 한 장이다. 실제 엔진 로더로 idle 1장·walk 8장, 전체 320×320·투명 테두리를 확인했고 브라우저에서 팔이 앞에 오는 자세와 반복 재생을 확인했다. 이동 속도·네이티브 입력·성능은 이번에 새로 검증하지 않았다.

현재 실행용 루트 `local-assets/nate-animation-review/current-characters`에는 v4를 넣고 이전 v3는 밑줄로 시작하는 `_nate-v3`로 보존해 기본 팩 검색에서 제외했다. 이전 원본·시험 팩을 삭제하지 않았으며 기본 예제 팩에는 적용하지 않았다. 미리보기는 v3와 v4의 팔 움직임을 비교한다.

## 긴 걷기와 선택한 A idle 적용

사용자는 실제 실행에서 v4 보행을 수용하고, 속도는 유지하면서 한 번 걷는 시간을 약 두 배로 늘리도록 요청했다. 행동의 목표 시간은 0.7~1.69초에서 1.4~3.38초로 바꾸고 중간 판단 창도 2초에서 4초로 늘려 조기 전환을 막았다. 속도 90픽셀/초와 걷기 PNG·FPS는 동일하다. 화면 경계나 여유 공간에 따라 일찍 멈추는 보정은 유지한다.

idle은 A 눈·시선 변화와 B 미세한 호흡·이완 두 후보를 만들고 사용자가 A를 선택했다. [눈 움직임 참고](https://www.animationmentor.com/blog/tutorial-animate-blinks-eye-movement/)와 [호흡 참고](https://www.animationmentor.com/blog/tutorial-animate-natural-breathing-loops/)를 검색해 확인했다. 내장 image_gen 도구의 전체 프롬프트는 `artwork/idle-options-prompts.md`, 비교 화면은 `idle-options.html`에 보존했다. B 첫 8장 생성은 약 10분간 결과가 없어 중단하고 4개 핵심 자세로 다시 생성했다.

A는 생성된 눈 패치만 원본의 눈 위치로 정렬·조립하고 몸 그림을 공통으로 사용했다. 최종 눈 영역 x=146~175, y=39~46 밖의 픽셀이 모든 프레임에서 동일함을 확인했다. B는 y=210 아래 다리·발 픽셀을 공통으로 고정했다. A 8장·B 4장 모두 320×320이다. B는 선택하지 않은 후보이며 실행 팩에 적용하지 않는다.

실제 A idle은 `frame_durations_ms = [2500, 400, 1000, 400, 2000, 60, 80, 60]`으로 재생한다. 긴 시선 유지와 약 0.2초 눈 깜빡임을 6.5초 루프에 배치했다. 이 항목은 idle에만 적용하며 길이·양수·총시간을 검증한다. 다음 프레임과 다음 행동 판단의 남은 시간 중 작은 값으로 타이머를 설정해 유휴 갱신을 줄이면서 행동 템포를 유지한다. 기존 FPS 팩은 기존 경로를 사용한다.
